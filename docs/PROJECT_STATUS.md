# CoderAI 学堂项目状态

更新时间：2026-07-20（北京时间）

## 本次盘点结论

- 当前课堂主流程已经可运行：管理员建课与发布、教师按学员/班级排课、学生学习与作品提交、教师批改和反馈查看均已形成闭环。
- 2026-07-20 学龄分类升级后的门禁基线为 66 项后端/工具测试、TypeScript/Vite 生产构建、18 条 Chrome 端到端测试和 LibreOffice 真实 PPTX 转换测试；Ant Design 主分包仍有体积警告。
- 教师与管理员职责已经拆分：教师面向全机构学生名单和本人获授权班级开展教学，管理员拥有全机构教学管理与独立系统管理能力；系统总览和教学总览不混合统计。
- 项目负责人已决定当前版本跳过 P0 失败证据链收集，因此 P0 与 P1 均无阻塞项；原计划仍有 P2 打包发布与云端规模化 18 项，另有 5 项工程与合规治理任务，共 23 项当前已知待办。
- 学生账号管理已经形成完整闭环：管理员“账号管理 → 学生开户”是唯一单独/CSV 批量开户入口，“教学管理 → 学员管理”只负责资料、状态、分班、密码、归档恢复和导出；教师可查询、分班和重置密码。
- 隐私与未成年人数据治理已经形成闭环：版本化政策、监护人授权、云端 AI 门禁、个人数据导出、学生数据删除和脱敏审计均已落地。
- 全局学生账号和班级多教师授权迁移已经实现：首次结构升级前自动备份 SQLite，重复启动不会重复归档学生或重复创建授权关系。
- 新课程层级已切换为“课程包 → 课程 → 课堂 PPT、工程包.md、成果包.md”，三类资料均可缺省；旧课程、课时、任务和提交保留历史兼容，不复制为新排课。
- 旧学生缺少有效用户名或密码时会停用归档并保留历史作品；已有完整账号继续保留。旧班级创建者迁移为首位授课教师，学生旧创建者绑定不再参与权限判断。
- P0 程序测试页面已从产品导航和前端源码中移除，历史验收后端仅允许管理员访问。失败证据实际覆盖仍为 `0/12`，豁免记录保留但不表示六类失败场景已验证。
- P0 历史基线、真实服务商矩阵、证据豁免和课堂通过标准保留在 `docs/P0_ACCEPTANCE.md`，不再作为教师端产品功能展示。

## 当前可用

### 学生端

- 管理员分配的用户名密码登录、自行注册关闭、账号停用和归档校验
- 独立学生工作台；小学低龄使用简化参数，小学高龄与初中高中使用完整创作参数
- AI 文字生成、图片生成、编程助手
- 视频生成任务提交、状态刷新、超时、失败重试、结果本地保存与过期链接恢复
- AI 服务能力预检，不支持的工具会提前禁用并提示
- 工作流模板运行、失败重试、运行历史和再次编辑
- 按个人或班级排课显示未开始、学习中和已逾期状态
- 课堂 PPT 的浏览器内 PDF 预览、工程包查看下载、首次提交后成果包解锁
- 课程作品提交、版本历史、逾期标记和教师反馈查看
- 班级素材分页及图片、视频、音频、文档预览
- 作品库筛选、Markdown 预览与编辑、图片本地/云端预览和原图下载、归档、回收站、恢复及提交作品删除保护
- 公共隐私政策查看、本人授权状态查看和个人数据 ZIP 导出

### 教师端

- 个人教师账号登录、密码修改、随机访问令牌和刷新会话
- 教学总览只统计本人获授权班级、班内未归档学生、排课提交和学员作品
- 班级创建、编辑、共同授课教师维护、安全删除和学员人数统计；只能修改本人获授权班级
- 全机构未归档学生查询、单独/批量分班和固定密码重置，不提供创建、导入、编辑、启停或归档入口
- 左侧三级课程目录只显示管理员已发布且向本人授权的课程包；在线查看课堂 PPT PDF，并查看和下载工程包、成果包 Markdown
- 按全机构未归档学生或本人获授权班级排课，课程选项同时受课程包白名单控制，支持单课、整包批排、时间调整、冲突提示和取消
- 获授权班级学员提交详情、作品预览、评分、反馈和批量操作；课程撤权或学员归档记录自动转为历史只读
- 获授权班级工作流编辑、模板发布和学员作品查看
- 课堂敏感内容检测、获授权班级图片复核和审核日志
- 当前教师账号的密码，以及“登录设备”“操作审计”两个可键盘切换的账号安全子页

### 管理员端

- 独立 `/admin/*` 管理控制台，系统总览不显示任何教师的班级、学员、作品或课堂任务
- 独立“教学管理”分组，覆盖全机构教学总览、班级、学生、课程管理、排课管理、作业批改、安全检测、工作流和学员作品
- 课程管理独占课程包、课程规则、三个可选资料槽位、发布归档、排序、教师/管理员作者选定、教师可见白名单以及带真实资料的 ZIP 导入导出权限
- “账号管理”集中教师/管理员账号、学生单独与 CSV 批量开户、当前管理员密码修改
- “教学管理 → 学员管理”维护学生资料、启停、分班、密码、归档恢复和导出，不重复提供开户入口
- 教师与管理员账号创建、角色调整、启停、临时密码重置和最后管理员保护
- “账号安全”仅保留登录设备与操作审计，管理员密码修改不再重复出现
- 全局多 AI 服务商、加密密钥、官方模型目录、文字/图片/视频能力路由、连通测试和调用统计
- 全局隐私政策、监护人授权规则和数据处理设置
- 日志、缓存、存储、文件一致性、完整压缩备份、恢复预检、冲突策略和失败回滚
- Ed25519 离线许可证、受信任发布者、签名插件、权限沙箱、升级、启停和卸载
- 内部验收后端与历史报告；产品控制台不显示 P0 或其他程序测试页面

### 数据与安全

- SQLite 元数据与本地文件分离保存
- AI API Key 使用当前 Windows 用户的 DPAPI 加密后保存，启动时会幂等迁移旧明文密钥
- 教师登录使用绑定具体账号的 2 小时访问令牌和 7 天轮换刷新令牌；学生使用独立持久化随机会话令牌，两类会话均支持后端注销和主动撤销
- 学生和职员密码均使用带随机盐的 PBKDF2 保存；学生初始/重置密码固定为 `bcm123456` 且不强制首次修改，职员临时密码仍强制首次修改
- 教师自行设置密码最低 8 位，弱密码允许使用但每次凭据登录提醒；管理员继续要求至少 10 位且包含字母、数字和特殊字符
- 教师和学生登录失败状态持久化到 SQLite，连续失败 5 次锁定 15 分钟并返回明确的重试时间
- 高风险职员操作由后端写入只读审计日志并记录操作者账号、姓名和用户 ID，密钥、密码、作品正文和批改正文不进入日志
- 所有业务时间按北京时间写入和显示
- 工作台左侧导航和顶部栏固定，侧栏菜单独立滚动，右侧内容区是唯一主滚动容器；顶部栏只显示身份，模型状态仅在模型服务页面提示
- 学生作品、视频任务和工作流记录先按学生身份隔离，再按历史班级快照和授课教师授权隔离
- `classroom_teachers` 支持班级多教师授权；有班级数据按授权过滤，无班级私有资源按创建者过滤，管理员不受限制
- `course_package_teachers` 支持课程包教师严格白名单；课程包默认隐藏，撤权保留排课和提交但关闭课程资料与写权限
- `course_packages.author_user_id` 将课程包作者约束为教师/管理员账号；旧自由文本作者已具备幂等回填和独立迁移快照
- 学生账号使用三类学龄，课程包使用结构化多选适用学龄；旧低阶/高阶值已具备幂等映射和独立迁移快照
- 用量和审核记录保存 `classroom_id` 快照；学生转班不改写历史快照，教师被移除授权后立即失去班级历史访问权
- 管理员系统接口使用 `require_admin`，教学接口同时执行职员会话、班级授权和资源快照校验
- 素材文件接口执行班级权限校验
- 已提交作品禁止直接删除，保留批改证据
- 班级存在学生或教学历史时禁止删除，避免历史权限和数据归属丢失
- 敏感词检测、文字/图片输出审核、学龄策略和服务能力检查
- 监护人联系方式使用 Windows DPAPI 加密；学生自助导出只包含掩码，教师授权导出才包含完整联系方式
- 学生数据删除覆盖作品、提交版本、工作流、视频、审核、用量、授权、AI 输入、缓存和旧本地备份，数据库失败时自动回滚已移动文件

- 学生和班级统一使用小学低龄、小学高龄、初中高中；班级另保留“混合学龄”。账号列表、编辑、CSV 模板/导入导出和 AI 工作台均使用新名称。
- 小学低龄继承原简化界面、卡通图片和 5 秒视频限制；小学高龄继承原完整创作能力；初中高中使用完整参数及更技术化的文字生成策略。学生无法通过伪造请求改变账号策略。
- 课程包的自由文本“适用年龄”改为一到三项“适用学龄”，创建时默认全选，详情、排课选项和学生课程页同步展示。适用学龄当前不追溯阻断已有排课。
- 迁移前创建 `coderai-before-school-stages.db`；旧 `junior/senior` 分别映射为小学低龄/小学高龄，不会自动归入初中高中。迁移、旧 CSV、旧备份和旧课程包导入保持兼容。

## 最近完成：课程包作者账号化

- 新建和编辑课程包时，作者由自由文本改为必选的教师/管理员账号下拉选择；学生账号、伪造文本和新选停用账号均由后端拦截。
- 课程包返回 `author_user_id` 和作者账号摘要，详情展示实时姓名与教师/管理员角色；停用历史作者可保留但不能用于新课程包。
- 旧课程包启动时优先回填原创建者，否则回退到管理员；ZIP 导入以当前管理员署名。迁移前使用 `coderai-before-course-package-authors.db` 独立快照。
- 作者署名与教师课程白名单继续分离，选定教师作者不会自动授予查看或排课权限。

## 最近完成：作业批改、课程目录与教师课程权限整改

- 批改分数改为表单控制的整数 `InputNumber`，满分独立显示；处理状态、分数、评语模板、反馈、优秀作品和保存按钮使用响应式网格，撤权及归档记录不渲染编辑表单，批量批改自动排除只读记录。
- 教师和管理员课程管理改为“教学管理 → 课程管理 → 课程包”的固定左侧三级目录。动态课程项使用 `/{role}/courses?package={id}`，刷新、前进后退和书签可恢复选择，右侧只显示概览或所选课程包全宽详情。
- 新增 `course_package_teachers` 严格白名单及管理员教师权限抽屉。现有、新建和 ZIP 导入课程包均默认隐藏，授权后教师才能预览课程资料和创建排课。
- 撤权不取消排课或学生学习提交。原教师保留必要历史只读字段；个人排课仅管理员接管，班级排课可由同时具备班级与课程权限的其他教师继续管理和批改。
- 课程包、排课和提交响应增加授权状态与准确的 `can_manage`/`can_review`，后端对详情、资料、新排课、排课更新取消和批改逐层强制校验；迁移前创建独立 SQLite 快照且不会自动授权旧课程包。

## 最近完成：课程体系、排课与归档学员权限重构

- 新教学结构统一为“课程包 → 课程 → 课堂 PPT、工程包.md、成果包.md”。课程包包含至少一门课程即可发布，三个资料槽位均可为空并可在发布和排课后继续补充或替换。
- 管理员独占课程包、课程规则、资料、发布、归档、排序、教师授权和 ZIP 导入导出写权限；教师课程管理仅用于查看本人获授权的已发布课程和备课。
- 教师和学生通过浏览器内 PDF Blob 预览课堂 PPT，不能下载 PPTX 或 PDF；教师可以查看和下载两类 Markdown，学生首次提交后解锁成果包。
- 排课管理支持按全机构未归档学员或本人获授权班级排课，单门课程和整包批排均生成独立排课记录，并支持时间调整、逾期提交、取消和评分规则快照。
- 学生端已串联排课状态、课程资料、作品提交、提交版本和教师反馈；教师批改页显示课程包、课程、排课目标和逾期状态。
- 归档学员不再出现在教师列表、统计或排课选项中，教师已知 ID 访问也会被拦截；原授权班级的历史作品和提交仅可只读查看，管理员仍保留全局管理权限。
- PPTX 使用 LibreOffice 后台转换，失败不阻止课程发布或排课；PDF 预览使用中性受鉴权响应并在前端恢复 MIME，避免外部下载管理器接管预览。
- 旧课程、课时、课堂任务和提交保留为只读历史；幂等迁移前已备份正式 SQLite 和课程素材，不会重置或复制真实历史数据。
