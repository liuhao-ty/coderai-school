# 单机构内测合规清单

本文件是产品和技术上线检查表，不是法律意见。机构应根据实际部署地、AI 服务商、招生方式和数据处理范围，由负责人或专业顾问确认适用义务。

## 1. 内测边界

- [ ] 仅向已签署内测安排的单一机构开放
- [ ] 不公开机构注册、不收款、不销售席位、不提供课程市场
- [ ] 同时在线席位上限固定为 50
- [ ] 学生只使用管理员创建的账号，不开放自助注册
- [ ] 浏览器版本只用于测试和内部运维，不公开发布学生 Web 入口
- [ ] 桌面端必须联网，不宣传完整离线能力

## 2. 主体与备案

- [ ] 明确云主机、域名、软件和数据处理的责任主体
- [ ] 完成域名实名认证
- [ ] 境内公开网络服务上线前确认 ICP 备案要求
- [ ] 确认公安联网备案要求和办理时间
- [ ] 结合实际模型、功能和服务方式确认算法备案、生成式 AI 责任或其他审批义务
- [ ] 保存云厂商、对象存储和 AI 服务商合同及数据处理条款

## 3. 隐私政策

管理员首次开放学生登录前应发布新版本政策，至少说明：

- 收集的账号、班级、课程、作品、提交、日志和监护人授权数据
- 处理目的、必要性、使用范围和保存位置
- 默认 365 天保留规则，以及例外、审批和删除方式
- 云端 AI 处理的数据类型、第三方服务商、可能的跨系统传输和失败处理
- 图片、视频、PPT、Markdown 和作品文件进入对象存储
- 学生/监护人的访问、更正、导出、撤回授权和删除渠道
- 账号安全、登录锁定、操作审计和备份保留
- 服务中止或内测结束时的数据导出与删除安排
- 联系方式和投诉/问题处理渠道

政策版本、发布时间、生效时间和管理员操作必须保留审计记录。

## 4. 未成年人和监护人授权

- [ ] 机构确定需要授权的年龄范围和授权主体
- [ ] 在允许学生调用云端 AI 前记录有效监护人授权
- [ ] 授权范围覆盖课程学习、云端 AI、作品存储和必要的第三方处理
- [ ] 授权凭证只保存编号或受控位置，不在系统中填写完整证件号码
- [ ] 撤回授权后立即停止新的云端 AI 调用，并明确既有课堂数据处理方式
- [ ] 教师只能查看教学所需字段，归档学生不进入日常维护和新排课
- [ ] 数据导出和删除操作验证学生身份并写入审计

## 5. AI 数据流向

每个启用服务商都应形成记录：

| 项目 | 必填内容 |
| --- | --- |
| 服务商与模型 | 正式名称、模型、接口区域 |
| 发送数据 | 提示词、图片、视频参考、必要上下文 |
| 使用目的 | 文字、图片、视频或审核 |
| 保留与训练 | 服务商条款中的保留、训练和退出设置 |
| 访问控制 | 机构管理员密钥、课程工具权限、学龄策略 |
| 删除渠道 | 服务商端和本系统端的删除方式 |
| 故障处理 | 超时、限流、余额不足、违规和人工复核 |

机构管理员必须使用机构自有密钥。不要使用开发者个人账号或把 Key 分发给教师/学生。

## 6. 内容安全与 AI 标识

- [ ] 输入敏感词与内容审核开启
- [ ] 图片结果在学生可见前执行自动审核或教师复核
- [ ] 小学低龄使用更严格的图片/视频策略和简化参数
- [ ] 违规、审核不可用和误拦截均有明确提示与人工处理入口
- [ ] AI 生成文字、图片和视频在作品详情或导出中保留生成来源标识
- [ ] 课堂规则明确禁止上传他人隐私、证件、违法内容或未经授权素材
- [ ] 教师能够处理违规作品，且审计不保存生成正文或敏感提示词

## 7. 账号与密码风险

当前学生初始/重置密码固定为 `bcm123456` 且不强制首次修改，是内测已确认风险。上线前必须同时执行：

- [ ] 用户名不可由姓名、手机号或学号简单推断
- [ ] 连续失败 5 次锁定 15 分钟已验证
- [ ] 教师/管理员可立即撤销会话并重置密码
- [ ] 学生账号只在受控渠道发放，不在公开群发布账号清单
- [ ] 每次重置写入操作者审计
- [ ] 内测结束后重新评估随机临时密码与首次登录改密

正式商业版不应直接沿用该风险接受项而不复审。

## 8. 数据安全

- [ ] API、更新和媒体访问全部使用 HTTPS
- [ ] PostgreSQL、Redis 和 MinIO 不直接暴露公网
- [ ] MinIO bucket 禁止匿名访问
- [ ] 桌面令牌保存在 Windows Credential Manager
- [ ] AI Key 使用 AES-GCM，服务器主密钥与数据库/备份分离
- [ ] 生产、备份和更新凭据均不进入 Git、日志和工单
- [ ] 机构租户和对象归属测试通过
- [ ] 高风险操作、会话撤销、密钥修改和数据删除均可审计
- [ ] 运维访问采用最小权限、MFA 和离职撤权流程

## 9. 保留、导出和删除

- [ ] 默认保留期限设置为 365 天
- [ ] 到期扫描只生成预览，不自动静默删除
- [ ] 例外保留有原因、目标和到期复核
- [ ] 删除前由管理员审批并输入精确确认文本
- [ ] 删除覆盖数据库、对象、缓存和可识别审计字段
- [ ] 机构导出不含密码、会话、AI Key 或监护人联系方式密文
- [ ] 平台备份保留为 30 个日备份和 12 个月度备份
- [ ] 备份过期数据的最终删除时间在政策中说明

## 10. 事件响应

上线前确定联系人和流程：

- 跨机构访问或对象越权：立即停服、保全日志、撤销会话和密钥
- 数据库损坏或对象丢失：停止写入，按恢复手册执行隔离演练
- AI Key 泄露：服务商撤销、服务器轮换、机构重新录入并审计
- 桌面更新异常：暂停清单、发布更高补丁版本或人工回退
- 不当内容：隐藏内容、教师复核、记录处理结果并按政策通知
- 未成年人数据请求：验证监护关系，按导出/删除流程处理

跨机构数据风险、无法恢复备份、数据库损坏或更新失败属于立即停止扩容条件。

## 11. 上线签字项

进入 5 至 10 人灰度前，应由以下责任人分别确认：

- 产品负责人：功能边界、固定学生密码风险、灰度与退出方案
- 教学负责人：课程权限、学龄策略、审核和课堂应急流程
- 机构负责人：学生名单、监护人授权、隐私政策和第三方服务商
- 技术负责人：租户隔离、备份恢复、监控、签名和密钥管理
- 合规负责人/顾问：备案、未成年人、AI 数据流向和生成内容标识

确认记录不得包含真实密码、AI Key、服务器主密钥或学生作品正文。
